# two-tower-recall

用双塔模型把用户和电影分别编码成向量，再用近似最近邻索引从全量库中毫秒级召回 Top-K，并用离线指标证明它优于基线。

## 任务定义

**输入**：一个用户的历史观影序列（用户 ID、电影 ID、评分、时间戳）。

**输出**：从全量 3,706 部电影中召回该用户最可能喜欢的 Top-K 部（默认 K=20），不包含他历史上已经看过的电影。

**Ground truth**：取每个用户时间上**最后一条**交互作为测试答案（leave-one-out），其余历史作为输入；验证集同理取倒数第二条。这样构造的目的是模拟线上场景——用过去预测未来。

**数据划分按时间进行，不随机打散**。随机切分会把未来的交互混进训练集，造成数据泄漏，离线指标虚高，线上效果崩掉。

**对应工业环节**：召回。推荐系统通常分「召回 → 排序」两级，召回负责从百万级（本项目 3,706 部）候选池中快速粗筛出几百个，排序再对这几百个精确打分。召回追求「快且不漏」，排序追求「准」。

## 数据

[MovieLens-1M](https://files.grouplens.org/datasets/movielens/ml-1m.zip)（GroupLens 公开数据集）：

| 指标 | 数值 |
|---|---|
| 评分数 | 1,000,209 |
| 用户数 | 6,040 |
| 电影数 | 3,706 |
| 时间跨度 | 2000-04-25 ~ 2003-02-28 |
| 用户-物品矩阵稀疏度 | 95.53% |

稀疏度的含义：6,040 × 3,706 ≈ 2,240 万个格子里只有 100 万个有评分，95% 以上是空的。这决定了不能依赖稠密的协同过滤矩阵，而要用向量化的方式建模。

## 评估指标

- **Recall@K**：前 K 个结果里命中的 ground truth 数量 ÷ 该用户 ground truth 的总数。衡量「该召回的有没有捞回来」，是召回环节最核心的指标。
- **HR@K**（Hit Rate）：前 K 个里**至少命中一个**就算 1，否则为 0，再对所有用户取平均。比 Recall 更宽松，适合每用户只有一个正确答案的 leave-one-out 设置。
- **NDCG@K**：不仅看有没有命中，还看命中的**位置**——排第 1 位比排第 20 位得分高（按 log 位置折损，再除以理想排序的得分做归一化）。用来衡量「排序质量」。

三者一起看：Recall 看覆盖，HR 看命中率，NDCG 看顺序是否正确。

## 如何复现

```bash
# 1. 建虚拟环境（需要 Python 3.14）
python3.14 -m venv .venv
source .venv/bin/activate

# 2. 装依赖
pip install -r requirements.txt

# 3. 下载数据（约 6 MB）
mkdir -p data/raw && cd data/raw
curl -O https://files.grouplens.org/datasets/movielens/ml-1m.zip
python3.14 -m zipfile -e ml-1m.zip .
cd ../..

# 4. 跑数据加载与统计
python -m recsys.data
```

预期输出：

```
评分数: 1000209
用户数: 6040
电影数: 3706
时间跨度: 2000-04-25 ... ~ 2003-02-28 ...
稀疏度: 95.53%
```
